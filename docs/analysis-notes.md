# 分析口径

当前项目的观察重点是decision signals and coverage。来源信息、观测记录与分析输出分别保存；报告保留生成时使用的来源标识，便于研究人员回看数据范围。输入观测的数值含义由调用方提供，项目不将报道计数解释为受众态度或传播因果。

## 排序口径

- 每个候选议题的分数 = 已有信号的加权平均（Σ 权重×信号总量 ÷ 已有信号权重之和）。缺失信号不按零分计。
- 支撑度 = 已有信号的权重占全部权重之比。支撑度低于 `min_support` 的议题列入“待补信息”，不参与名次，也不被视为低优先级。
- 通过 `candidates` 登记的候选议题即使完全没有数据，也以支撑度 0 出现在待补信息中，而不是从名单里消失。
- 不同信号数值之间的可比性由调用方保证；项目只按给定权重汇总，不替数据做口径假设。

## 决定留档

- 每次月度决定保存：观察数据快照（含 SHA-256 哈希）、口径（权重与支撑度阈值）、当时的排序与待补名单、选定议题与选择理由。
- 档案只增不改：同一 `decision_id` 不能写第二次。补录或修正数据后，重算的是“待决策名单”（`pending` / `recompute_pending`），已留档决定不变。
- `verify` 重新计算快照哈希并按留档口径重排，能发现留档文件内部的不一致（数据或结果被改动）。要防住有意的整体替换，档案目录应置于版本控制或只读存储之下。

## 变化归因

- 对比两版数据时，名次变化的归因只是讨论线索：新增来源/地区记为“覆盖补齐”，同一批来源的数值变化记为“信号变化”，既有记录被改动记为“记录修正”。
- 归因帮助团队分辨名单翻转是否源于数据补齐（例如某渠道补录、某地区样本构成改变），但不证明因果。

## 边界

分析输出仅用于讨论资源安排。排序是按既定口径对已有信号的加权汇总，不构成客观因果，也不是唯一正确的顺序；最终取舍与理由由负责人作出并随决定留档。
